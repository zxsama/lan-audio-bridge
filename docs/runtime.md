# Runtime contract

This document describes the container's runtime interface and routing invariants. For setup and validation commands, see [development.md](development.md) and the [README](../README.md).

Target: Linux amd64 with Docker. Single locally built image, four independently enabled phone receivers (Shairport Sync, gmrender-resurrect, librespot, experimental MiPlay) and an optional VBAN desktop receiver, PulseAudio owns the configured ALSA playback device. Apple Music and multiroom are out of scope. Do not require a web UI, Docker socket, or privileged mode.

Runtime interface:
- `python3 /app/runtime.py` is the container command; `python3 /app/healthcheck.py` is the Docker health check.
- Environment: `DEVICE_NAME=NAS Audio`, `AUDIO_DEVICE` (required stable ALSA name in hardware mode), `AUDIO_MODE=alsa|null` (null for tests only), `AVAHI_MODE=internal|external` (default `internal`), `SAMPLE_RATE=48000`, `OUTPUT_VOLUME=100` (percent 0..100), `ENABLE_AIRPLAY=true`, `ENABLE_DLNA=true`, `ENABLE_SPOTIFY=true`, `ENABLE_MIPLAY=true`, `MIPLAY_PORT=8899`, `DLNA_BUFFER_MS=1000` (0..5000; 0 uses upstream defaults), `OUTPUT_BUFFER_MS=200` (50..1000), `NETWORK_INTERFACE` optional, `DLNA_PORT=49494`, `AIRPLAY_PORT=7000`, `SPOTIFY_PORT=24879`, `OUTPUT_SCHEDULING=timer|interrupt` (default `timer`), `OUTPUT_FRAGMENT_MS=2` (1..20), `OUTPUT_FRAGMENTS=3` (2..8), `PULSE_REALTIME=false`, `OUTPUT_IDLE_SUSPEND_MS=0` (0..600000, native desktop backend), `DESKTOP_KEEP_AWAKE=false`, `DIAGNOSTICS_STATUS=false`.
- `OUTPUT_SCHEDULING=interrupt` loads the ALSA sink with `tsched=0` and `OUTPUT_FRAGMENTS` periods of `OUTPUT_FRAGMENT_MS` each (s16le stereo request, converted by `plughw` if needed). The default timer scheduling keeps a large hardware buffer and raises its wakeup watermark after scheduling delays; a measured USB DAC held 17–38 ms in the ALSA queue. `PULSE_REALTIME=true` starts PulseAudio with `--realtime=yes --high-priority=yes` and the native desktop receiver with `--realtime`; both stay within the container's `rtprio`/`nice` ulimits, add no capability, and fall back to nice −11 or normal priority when the kernel refuses realtime scheduling. `OUTPUT_IDLE_SUSPEND_MS` keeps the muted output running for that long after both lanes go idle before the native receiver suspends it; a measured USB DAC needed ~120 ms to resume, and audio queued during that wake persisted as ~20 ms of extra latency for about 15 s. `DESKTOP_KEEP_AWAKE=true` (native backend) keeps the muted output running for as long as VBAN packets, silence included, keep arriving, and resumes it when a sender connects; the output suspends `OUTPUT_IDLE_SUSPEND_MS` after packets stop. Digital silence still ends the desktop session, so phone mixing gain is unaffected. `DIAGNOSTICS_STATUS=true` copies `status.json` to `/data/diagnostics/status.json` once per second so the host can read counters without container access; it contains no credentials. The native receiver also logs one-line `vban-pulse:` diagnostics (session trace, underflow, server overflow, connect/disconnect) to the container log. `status.output` reports the configured values.
- Persistent directory `/data`, ephemeral runtime directory `/run/lan-audio`, status JSON `/run/lan-audio/status.json`. Never store credentials in logs or status. Stable DLNA UUID persisted under /data.
- Pulse server `unix:/run/lan-audio/pulse.sock`. Sinks `airplay_bus`, `dlna_bus`, `spotify_bus`, `miplay_bus`, `discard`, `output`. Never load rescue-streams / automatic device switching. In null mode output is a null sink. Hardware mode uses module-alsa-sink with AUDIO_DEVICE, not automatic default selection.
- All receivers write only to their bus. The phone owner has one module-loopback from its bus monitor to output. With desktop enabled, a second independently managed loopback connects desktop_bus; the phone coordinator still selects only one phone source. Phone transitions unload before load; failures fail closed. At startup and when both lanes are idle, output is muted and suspended with no route. Playback resumes output before creating the new loopback, then unmutes it. This releases an ALSA device while idle instead of continuously writing silent PCM.
- `OUTPUT_VOLUME` defaults to 100 (0 dB), with explicit values from 0 to 100 preserved. MiPlay volume is shared across authenticated control connections and applied only to its input bus; reconnecting does not reset it. The shared value is a target applied asynchronously, and resets to the initial value when the receiver process restarts.
- Coordinator polls actual Pulse sink-inputs (corked vs active) every 0.2s, or 0.05s when desktop input is enabled. Newly active source can take over; stop/restart losing receiver so it does not silently advance/reclaim on next track. Same protocol concurrency is delegated to receiver. Late disappearance of old streams must not release new owner. Desktop audio is excluded from phone arbitration and preemption. Restarting a receiver briefly reannounces it. Do not promise phone UI pause. No automatic fallback to old source when owner stops.
- Runtime supervisor nonblocking restarts preempted receivers; a dead core dependency (PulseAudio, internal dbus/avahi, nqptp if used) exits the whole container for restart. Receiver crash restart with bounded backoff. SIGTERM shuts down all children; use process groups.
- Internal discovery starts the bundled D-Bus and Avahi. External discovery starts neither: receivers use only the filtered socket at `/run/dbus/system_bus_socket`. Startup, health checks and periodic supervisor probes call Avahi `GetVersionString`; loss of availability exits the audio process for the Docker restart policy. An unhealthy flag alone does not restart a container.
- `compose.host-avahi.yaml` is an override specifically for `compose.yaml`. Only its isolated `discovery-proxy` sidecar sees the host `/run/dbus` directory at `/run/host-dbus:ro`; audio sees the separate `avahi-bus` volume read-only at `/run/dbus`. The sidecar has no network, drops all capabilities, uses a read-only root filesystem and runs `python3 /app/avahi_proxy.py`. Do not mount the raw host bus into audio or run this proxy alongside unrestricted audio processes in one container.
- The proxy uses method filters rather than broad `--talk` or `--own`: selected read-only Server methods, `EntryGroupNew`, `EntryGroup.*`, read-only introspection/properties and `Peer.Ping`, plus Server/EntryGroup `StateChanged` signals. Dynamic entry-group paths are supported. `SetHostName` and calls to unrelated host services are not allowed. Standard filtered bus bookkeeping remains available; this is not unrestricted host bus access.
- External discovery requires audio to share the host network namespace: the advertised host addresses and receiver ports must identify the same reachable machine. Host Avahi interface/publication policy still applies. `NETWORK_INTERFACE` cannot override that policy. See [host-avahi.md](host-avahi.md) for installation and recovery acceptance boundaries.
- Include nqptp for AirPlay 2. Pinned Shairport 5.6.2 and librespot 0.8.0 use their Avahi backends; gmrender comes from Debian trixie. AirPlay 2 startup requires nqptp UDP319/320 and no conflicting timing service. Reusing host Avahi does not resolve PTP/SSDP conflicts.
- Logs stdout/stderr, bounded via Compose logging. Production host network + /dev/snd mapping. Compose test variant bridge + null output, with isolated names and data; tests must target the isolated instance rather than a production deployment.

MiPlay publishes `_mi-connect._udp` through the existing Avahi EntryGroup API and a unique UUID hostname bound to the selected IPv4 address. It does not open a second mDNS socket. Its TCP control port is carried in appsData; the advertised UDP 56666 value is a protocol identity field, not an implemented CoAP endpoint. See [miplay.md](miplay.md) for compatibility limits.

DLNA uses a bounded Pulse PCM ring buffer (`pulsesink buffer-time`, microseconds), retaining normal clock synchronization and upstream pause/seek handling. It does not enable gmrender 0.3 BUFFERING callbacks. The output loopback target latency is separately configurable; neither setting solves indefinite network stalls. Status includes configured values in `buffers.dlna_ms` and `buffers.output_ms`.

## Desktop input and simultaneous mixing

`ENABLE_DESKTOP=false` preserves the phone-only behavior. When enabled, `VBAN_SOURCE_IP` is required; `VBAN_PORT=6980`, `VBAN_STREAM_NAME=Windows`, `DESKTOP_BUFFER_MS=50` (20..500), `DESKTOP_VOLUME=100` (0..100), and `DESKTOP_IDLE_MS=500` (200..5000) configure the independent receiver. The desktop format is limited to 48 kHz, stereo, signed 16-bit little-endian PCM. See [desktop setup](desktop-audio.md).

The desktop receiver writes active-session state, PID, freshness and generation to `/run/lan-audio/desktop.json`. The runtime acknowledges the same generation with a managed route in `status.desktop` before the receiver submits audio. The receiver bounds queued data and releases its player on digital silence or valid-stream timeout. A stale or dead receiver loses only the desktop route.

`route_module` and `owner` continue to describe the phone lane. `desktop` adds `enabled`, `active`, `generation` and `route_module`; `buffers.desktop_ms` records the desktop route target. State is playing when either lane has a route. Health accepts desktop-only playback and requires its supervised process when enabled.

In dual-lane mode, a new loopback is staged on discard, assigned its gain, then moved to output. Only the two registered routing module IDs are allowed to feed output. With both routes active, each has linear gain 0.5 (approximately -6.02 dB); a sole route returns to its unattenuated gain, with the desktop volume multiplier preserved. Phone switching avoids temporarily restoring desktop gain between routes. Gains are on route sink-inputs, not protocol buses or the global output volume. Normal lane cleanup leaves the other lane running; core failure and shutdown revoke all routes and suspend output.
