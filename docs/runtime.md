# Runtime contract

This document describes the container's runtime interface and routing invariants. For setup and validation commands, see [development.md](development.md) and the [README](../README.md).

Target: TrueNAS SCALE, Linux amd64. Single locally built image, four independently enabled receivers (Shairport Sync, gmrender-resurrect, librespot, experimental MiPlay), PulseAudio owns the USB ALSA device. Apple Music and multiroom are out of scope. Do not require a web UI, Docker socket, or privileged mode.

Runtime interface:
- `python3 /app/runtime.py` is the container command; `python3 /app/healthcheck.py` is the Docker health check.
- Environment: `DEVICE_NAME=NAS Audio`, `AUDIO_DEVICE` (required stable ALSA name in hardware mode), `AUDIO_MODE=alsa|null` (null for tests only), `AVAHI_MODE=internal|external` (default `internal`), `SAMPLE_RATE=48000`, `OUTPUT_VOLUME=70` (percent 0..100), `ENABLE_AIRPLAY=true`, `ENABLE_DLNA=true`, `ENABLE_SPOTIFY=true`, `ENABLE_MIPLAY=true`, `MIPLAY_PORT=8899`, `DLNA_BUFFER_MS=1000` (0..5000; 0 uses upstream defaults), `OUTPUT_BUFFER_MS=200` (50..1000), `NETWORK_INTERFACE` optional, `DLNA_PORT=49494`, `AIRPLAY_PORT=7000`, `SPOTIFY_PORT=24879`.
- Persistent directory `/data`, ephemeral runtime directory `/run/lan-audio`, status JSON `/run/lan-audio/status.json`. Never store credentials in logs or status. Stable DLNA UUID persisted under /data.
- Pulse server `unix:/run/lan-audio/pulse.sock`. Sinks `airplay_bus`, `dlna_bus`, `spotify_bus`, `miplay_bus`, `discard`, `output`. Never load rescue-streams / automatic device switching. In null mode output is a null sink. Hardware mode uses module-alsa-sink with AUDIO_DEVICE, not automatic default selection.
- All receivers write only to their bus. Sole output route is one module-loopback from owner bus monitor to output. Unload before load; failures fail closed. No route at startup or idle.
- Coordinator polls actual Pulse sink-inputs (corked vs active) every 0.2s. Newly active source can take over; stop/restart losing receiver so it does not silently advance/reclaim on next track. Same protocol concurrency is delegated to receiver. Late disappearance of old streams must not release new owner. Restarting a receiver briefly reannounces it. Do not promise phone UI pause. No automatic fallback to old source when owner stops.
- Runtime supervisor nonblocking restarts preempted receivers; a dead core dependency (PulseAudio, internal dbus/avahi, nqptp if used) exits the whole container for restart. Receiver crash restart with bounded backoff. SIGTERM shuts down all children; use process groups.
- Internal discovery starts the bundled D-Bus and Avahi. External discovery starts neither: receivers use only the filtered socket at `/run/dbus/system_bus_socket`. Startup, health checks and periodic supervisor probes call Avahi `GetVersionString`; loss of availability exits the audio process for the Docker restart policy. An unhealthy flag alone does not restart a container.
- `compose.host-avahi.yaml` is an override specifically for `compose.yaml`. Only its isolated `discovery-proxy` sidecar sees the host `/run/dbus` directory at `/run/host-dbus:ro`; audio sees the separate `avahi-bus` volume read-only at `/run/dbus`. The sidecar has no network, drops all capabilities, uses a read-only root filesystem and runs `python3 /app/avahi_proxy.py`. Do not mount the raw host bus into audio or run this proxy alongside unrestricted audio processes in one container.
- The proxy uses method filters rather than broad `--talk` or `--own`: selected read-only Server methods, `EntryGroupNew`, `EntryGroup.*`, read-only introspection/properties and `Peer.Ping`, plus Server/EntryGroup `StateChanged` signals. Dynamic entry-group paths are supported. `SetHostName` and calls to unrelated host services are not allowed. Standard filtered bus bookkeeping remains available; this is not unrestricted host bus access.
- External discovery requires audio to share the host network namespace: the advertised host addresses and receiver ports must identify the same reachable machine. Host Avahi interface/publication policy still applies. `NETWORK_INTERFACE` cannot override that policy. See [host-avahi.md](host-avahi.md) for installation and recovery acceptance boundaries.
- Include nqptp for AirPlay 2. Pinned Shairport 5.6.2 and librespot 0.8.0 use their Avahi backends; gmrender comes from Debian trixie. AirPlay 2 startup requires nqptp UDP319/320 and no conflicting timing service. Reusing host Avahi does not resolve PTP/SSDP conflicts.
- Logs stdout/stderr, bounded via Compose logging. Production host network + /dev/snd mapping. Compose test variant bridge + null output, isolated names/data; do not touch NAS.

MiPlay publishes `_mi-connect._udp` through the existing Avahi EntryGroup API and a unique UUID hostname bound to the selected IPv4 address. It does not open a second mDNS socket. Its TCP control port is carried in appsData; the advertised UDP 56666 value is a protocol identity field, not an implemented CoAP endpoint. See [miplay.md](miplay.md) for compatibility limits.

DLNA uses a bounded Pulse PCM ring buffer (`pulsesink buffer-time`, microseconds), retaining normal clock synchronization and upstream pause/seek handling. It does not enable gmrender 0.3 BUFFERING callbacks. The output loopback target latency is separately configurable; neither setting solves indefinite network stalls. Status includes configured values in `buffers.dlna_ms` and `buffers.output_ms`.
