## 最终镜像回归

在本机 WSL Docker 的独立容器中运行，使用 null 输出，不映射真实声卡或发布端口。

- C11 构建启用 `-Wall -Wextra -Werror`，完成镜像内依赖与上游哈希检查。
- 173 项 Linux 单元测试全部通过，无跳过，包含原有 Python 后端、MiPlay 和新增原生控制与路由检查。
- 原生后端真实 UDP PCM 集成通过：四手机总线、12 种有向切换、独立音量与停止、来源校验、丢包/重排恢复及重复启停。
- 桌面持续播放跨越 949 个 50 ms 检查窗口，最小 RMS 为 3533.9；该窗口检查不能证明逐采样无缺口。
- 短提示音唤醒观察为 13.5 ms，包含软件录音开销，不是物理输出延迟。
- 满幅双路混音峰值 32758/32767，没有超过 PCM16 范围。
- 终止桌面接收进程后，手机路由及手机接收进程保持，桌面接收自动恢复；44 个连续 50 ms 窗口最小 RMS 为 3535.1。
- 实际原生流使用 `speex-float-5`；两路结束后，原生流暂停，公共输出挂起。

## 独立时钟与队列测试

最终 C 源码分别接受 ±200 ppm 发送偏差，各持续至少 120 秒。两组严格测试均无媒体期欠载，最长近零段均为一个正弦过零采样。软件观察 P95 分别为 15.54 ms 和 14.86 ms。

固定输出最低缓冲 20 ms 的私有模拟也通过：实际协商客户端 24 ms、输出 20 ms，接收器目标为 44 ms。观察 P95 为 41.14 ms，使用单独的 55 ms 验收门槛。这验证了设备缓冲下限的适配，没有证明该设备可以达到低于 20 ms。

测试同时覆盖 managed 握手、手机切换预留增益、服务端调速确认和 JSON 最大计数容量。方法、最终指标与早期失败记录见[延迟验证](latency.md)和[原生接收器说明](../native/README.md)。

## Windows 与部署边界

Windows 音量和托盘修复沿用已验证的 [0.3.1](verification-0.3.1.md)，本版不再修改安装脚本。额外实验使用同一 QPC 时钟测量发送端提交到本机 VBAN 接收；最激进的已测配置中位数仍为 45.04 ms。测试后已恢复 3072/512 常用配置。

本版尚未在目标 NAS 上部署，未验证真实声卡、手机实际协议连接、Windows 登录后恢复或数小时连续播放。先前的 NAS 软件观察约 241 ms 来自旧接收配置，不能视为本版结果。**Windows 到物理输出的 10–20 ms 目标尚未达到。**

源代码、共享目录和镜像交付不等同于运行中的应用已升级。公共默认后端保持 `python`，原生后端须显式选择；两个后端共用原有身份与数据目录。
