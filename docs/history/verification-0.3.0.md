# 0.3.0 软件验证

验证日期：2026-11-06。环境：Windows 11、Ubuntu WSL、本机 Docker、Linux amd64。镜像 `lan-audio-bridge:0.3.0`，ID `sha256:2d43454dbd6ae2dbe287438fb8ec78d9285c5f6c59c276ddfe0e890f24cf3129`。

所有音频测试使用独立 null 输出容器。未修改 Windows 默认音频设备、安装音频驱动或操作 TrueNAS 应用。

## 软件延迟

`tests/desktop_latency.py --markers 30` 在同一个容器中记录 UDP 提交时刻，以及录音进程收到输出标记的时刻。各模式为一次冷启动加 29 个稳态标记：

| 模式 | 冷启动 | 稳态中位数 | 稳态 P95 | 稳态最大值 |
| --- | ---: | ---: | ---: | ---: |
| 电脑单独播放 | 134.0 ms | 127.3 ms | 130.4 ms | 130.5 ms |
| 电脑与 DLNA 输入总线混音 | 94.6 ms | 97.2 ms | 98.6 ms | 98.7 ms |

此外，从 Windows Python 进程发送真实 UDP，经 WSL Docker 接收并录制输出，再通过 WSL 标准输出回传 Windows 计时：冷启动 133.4 ms，9 个稳态标记中位数 138.3 ms，最大值 143.6 ms，结束后恢复 idle。

以上包含客户端、录音、进程调度，以及 Windows 测试中的回传开销。它们不包含 Voicemeeter 驱动、物理局域网、NAS 声卡或音响，不能当作硬件端到端延迟；不同模式的调度与缓冲状态也不同，不能据此宣称混音使声音更快。此次短时样本不证明数小时无时钟漂移或卡顿。

## 已修复的验证问题

- 默认 null sink 的两秒空闲调度窗口可能造成首次播放阻塞。电脑输入、混音暂存 sink，以及桌面测试的 null 输出使用 `norewinds=true` 限制该窗口；实际 ALSA 输出不使用此测试配置。
- `pactl` 带负号的 dB 参数是相对调整，会在每次切换时继续降低音量。混音增益改用绝对 Pulse 音量，录音验证多次切换后的幅度保持一致。
- 握手前的短通知不再被普通实时队列时限提前删除；停止时保留路由直到下游缓冲排空。

实现依据：[VBAN PCM 规范](https://vb-audio.com/Voicemeeter/VBANProtocol_Specifications.pdf)、[PulseAudio null sink 源码](https://github.com/pulseaudio/pulseaudio/blob/v17.0/src/modules/module-null-sink.c)。协议接收、运行时和实际音频测试均随仓库提供；复现方式见[开发文档](../development.md)。
